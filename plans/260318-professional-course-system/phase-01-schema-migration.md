## Overview

- **Priority:** P1 (blocks all other phases)
- **Status:** pending
- **Effort:** 3h
- **Description:** Add subject/ageGroup enums to Course, create CourseReview model, add denormalized rating fields. Zero breaking changes.

## Key Insights

- Existing `AgeGroup` enum has: UNDER_3, AGE_3_5, AGE_6_8, AGE_9_12, ALL_AGES
- Need to extend with: AGE_4_6, AGE_7_9, AGE_10_12 for course-specific ranges
- Course model currently has no classification fields -- all filtering impossible
- ParentAccount needs new `courseReviews` relation
- All new fields nullable or have defaults -- safe for existing data

## Requirements

### Functional
- Add `CourseSubject` enum with MATH, ENGLISH, SCIENCE, ART, MUSIC, OTHER
- Extend `AgeGroup` enum with AGE_4_6, AGE_7_9, AGE_10_12 values
- Add subject, ageGroup, reviewAverageRating, reviewCount to Course model
- Create CourseReview model with unique constraint [courseId, parentId]
- Add relation from ParentAccount to CourseReview

### Non-Functional
- Zero downtime migration
- No data loss for existing courses
- Indexes on filter query paths

## Architecture

```
Course (existing) ── add fields ──> subject?, ageGroup?, reviewAverageRating?, reviewCount
    │
    └── reviews[] ──> CourseReview (new model)
                           │
ParentAccount ── courseReviews[] ──┘
```

## Implementation Steps

1. **Add CourseSubject enum** to `prisma/schema.prisma`:
   ```prisma
   enum CourseSubject {
     MATH
     ENGLISH
     SCIENCE
     ART
     MUSIC
     OTHER
   }
   ```

2. **Extend AgeGroup enum** -- add AGE_4_6, AGE_7_9, AGE_10_12 after existing values

3. **Add fields to Course model:**
   ```prisma
   subject              CourseSubject?
   ageGroup             AgeGroup?
   reviewAverageRating  Float?
   reviewCount          Int              @default(0)
   reviews              CourseReview[]

   @@index([subject, isPublished])
   @@index([ageGroup, isPublished])
   ```

4. **Create CourseReview model:**
   ```prisma
   model CourseReview {
     id         String   @id @default(cuid())
     courseId   String
     parentId   String
     rating     Int      // 1-5
     comment    String?
     isApproved Boolean  @default(false)
     createdAt  DateTime @default(now())
     updatedAt  DateTime @updatedAt

     course  Course        @relation(fields: [courseId], references: [id], onDelete: Cascade)
     parent  ParentAccount @relation(fields: [parentId], references: [id], onDelete: Cascade)

     @@unique([courseId, parentId])
     @@index([courseId, isApproved, createdAt])
   }
   ```

5. **Add relation to ParentAccount:**
   ```prisma
   courseReviews CourseReview[]
   ```

6. **Run migration:**
   ```bash
   pnpm prisma migrate dev --name add-course-filtering-and-reviews
   ```

7. **Verify:** `pnpm prisma generate` + compile check

8. **(Optional) Seed existing courses** with subject/ageGroup based on slug patterns:
   - `abeka-*` -> subject: ENGLISH
   - `lfen-*` -> subject: ENGLISH
   - `lfcn-*` -> subject: OTHER (Chinese)
   - All -> ageGroup: ALL_AGES (refine later via admin)

## Risk Assessment

| Risk | Impact | Mitigation |
|------|--------|------------|
| AgeGroup enum extension conflicts with BlogPost usage | Low | BlogPost uses UNDER_3/AGE_3_5/AGE_6_8/AGE_9_12; new values AGE_4_6/AGE_7_9/AGE_10_12 don't overlap |
| Existing courses have subject=null | Low | Filter UI defaults to "All" which skips null filter |
