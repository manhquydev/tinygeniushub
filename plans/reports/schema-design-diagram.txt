  Index: [isApproved DESC, createdAt]

PATCH /api/admin/reviews/[id]
{
  isApproved: true,
  approvedBy: "admin@site.com"

     ↓
Course.reviewAverageRating
Course.reviewCount
  ↓ AUTO-UPDATE on approval
     ↓
Appears on storefront:
  Index: [courseId, isApproved, createdAt DESC]
     ↓
Display to users (max 10, newest first)


DENORMALIZATION STRATEGY
════════════════════════

Problem: Aggregating 1000+ reviews per query = 100-300ms

Solution: Cache summary on Course model

On EVERY review action (create/approve/reject):
  1. Update Course.reviewAverageRating (computed from approved reviews)
  2. Update Course.reviewCount (approved + not deleted)

Trade-off:
  GAIN: Storefront queries: <1ms vs 100-300ms
  COST: Staleness (acceptable for reviews, eventual consistency)
  SAFETY: Nightly batch job reconciles any divergence

Sync update code:
┌─────────────────────────────────┐
│ async updateCourseRatingStats    │
│ (courseId: string) {             │
│   const stats = aggregate({      │
│     courseId,                    │
│     isApproved: true,            │
│     deletedAt: null              │
│   });                            │
│                                  │
│   await Course.update({          │
│     where: { id: courseId },     │
│     data: {                      │
│       reviewAverageRating:       │
│         stats._avg.rating,       │
│       reviewCount: stats._count  │
│     }                            │
│   });                            │
│ }                                │
└─────────────────────────────────┘

QUERY PERFORMANCE COMPARISON
═════════════════════════════

Scenario: Get 10 approved reviews, sorted by date

WITHOUT INDEX:
  └─ Full table scan CourseReview
  └─ Filter by courseId (500k rows → 10 rows)
  └─ Filter by isApproved (scan ALL)
  └─ Time: 50-100ms ❌

WITH INDEX [courseId, isApproved, createdAt DESC]:
  └─ Index seek to courseId + isApproved
  └─ Already sorted by createdAt DESC
  └─ Return top 10
  └─ Time: 1-3ms ✅

Improvement: 20-50x faster
