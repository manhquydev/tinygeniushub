================================================================================
TECHNICAL DECISIONS MADE
================================================================================

1. USE PRISMA ENUMS
   Rationale: Type-safe, DB-enforced constraints, IDE autocomplete
   Alternative: String with runtime validation (error-prone)

2. DENORMALIZE RATING STATS
   Rationale: <1ms storefront queries vs 100-300ms aggregation
   Trade-off: Eventual consistency (acceptable for reviews)
   Mitigation: Sync update on actions + optional nightly job

3. REQUIRE ADMIN APPROVAL
   Rationale: Quality control, prevent spam
   Alternative: Auto-publish from enrolled parents

4. SOFT DELETE REVIEWS
   Rationale: Audit trail, referential integrity
   Alternative: Hard delete (data loss)

5. ONE REVIEW PER PARENT
   Rationale: Prevent duplicates, allow updates
   Implementation: UNIQUE constraint on (courseId, parentId)
